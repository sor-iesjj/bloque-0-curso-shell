## Qué necesitas entender antes de empezar

- **Máquina virtual (VM):** ordenador simulado por un programa. Tendrá memoria, procesadores y disco propios, aunque se ejecutará dentro del ordenador de Windows.
- **VirtualBox:** el programa que crea y ejecuta esa VM. La ventana de VirtualBox muestra y configura la máquina de pruebas.
- **Anfitrión:** el ordenador físico con Windows. **Invitado:** Ubuntu, que instalarás dentro de la VM.
- **Disco virtual dinámico:** archivo guardado en Windows que Ubuntu verá como su disco. El tamaño elegido es un *límite máximo*: el archivo crecerá conforme Ubuntu guarde datos. La ISO y las instantáneas también ocupan espacio en Windows.
- **NAT:** ajuste de VirtualBox que permite a la VM salir a Internet por la conexión del anfitrión. No tendrás que conocer ni modificar la dirección de la red del centro.
- **Instalación manual y desatendida:** en la manual contestarás las pantallas del instalador; en la desatendida VirtualBox puede contestarlas automáticamente. Elegimos **manual** porque aquí debes ver y justificar esas decisiones. [Manual oficial de VirtualBox](https://docs.oracle.com/en/virtualization/virtualbox/7.2/user/create-vm.html).

## Comprueba que este ordenador puede ejecutar VirtualBox

Esta guía requiere un anfitrión Windows x86-64 compatible con la versión de VirtualBox disponible y una VM invitada x86-64 (Ubuntu Server amd64). Comprueba la arquitectura real antes de descargar o instalar. El manual de VirtualBox 7.2 indica que un host Arm64 con Windows 11 solo admite invitados Arm64; ejecutar un invitado x86 en Arm no está soportado. Por eso, si el tipo de sistema indica ARM, detente: no descargues una ISO amd64 ni intentes forzar la VM. La versión vigente y los instaladores se consultan en [VirtualBox Downloads](https://www.virtualbox.org/wiki/Downloads). Si el instalador no ofrece el paquete adecuado, la virtualización aparece deshabilitada, el equipo está gestionado o VirtualBox no inicia una VM de 64 bits, consulta al profesor; no cambies BIOS/UEFI ni políticas del equipo.

1. En Windows abre **Configuración → Sistema → Acerca de** y comprueba «Tipo de sistema». Debe indicar procesador x64, no ARM.
2. En el Administrador de tareas abre **Rendimiento → CPU** y localiza «Virtualización». Si aparece «Deshabilitada», detente y consulta; no cambies firmware por tu cuenta.
3. Si VirtualBox no está instalado en Casa, descarga el instalador Windows x86-64 desde [VirtualBox Downloads](https://www.virtualbox.org/wiki/Downloads) y sigue el asistente con una cuenta autorizada. Si no tienes permisos, cancela y consulta.
4. Abre VirtualBox y comprueba que llega a la ventana principal. Anota versión, tipo de sistema, estado de virtualización y cualquier bloqueo real en la nota.

No todos los ordenadores pueden ejecutar la VM. Si este equipo no cumple, detén la práctica hasta que el profesor asigne uno compatible; no improvises otra arquitectura. Consulta el [manual oficial de VirtualBox](https://www.virtualbox.org/manual/UserManual.html).

## Comprueba la ruta del disco virtual antes de abrir el asistente

Cierra cualquier asistente de creación que esté abierto. Desde Git Bash, sitúate en la raíz física `SOR_Shell_Casa` y ejecuta primero estas comprobaciones:

```bash
command -v git >/dev/null 2>&1 || { echo "PARADA: Git no está disponible"; exit 1; }
pwd -P
P=$(pwd -P)
N=$(printf '%s' "$P" | tr '[:upper:]' '[:lower:]')
case "$N" in */sor|*/sor/*|*/boveda_sor|*/boveda_sor/*) echo "PARADA: esta ruta está dentro de SOR o Boveda_SOR"; exit 1;; esac
case "$N" in */sor_shell_casa) ;; *) echo "PARADA: abre la raíz física SOR_Shell_Casa; no continúes desde otra carpeta"; exit 1;; esac
if git rev-parse --show-toplevel >/dev/null 2>&1; then echo "PARADA: hay un repositorio Git heredado"; exit 1; fi
test -d "$P/VMs" || { echo "PARADA: no existe VMs dentro de la raíz SOR_Shell_Casa; vuelve al README de contexto"; exit 1; }
```

Qué hace cada línea del bloque:

1. **Línea 1:** comprueba que Git está disponible y detiene el recorrido si falta.
2. **Línea 2:** enseña la ruta física actual.
3. **Línea 3:** guarda esa ruta en `P`.
4. **Línea 4:** convierte la ruta a minúsculas para comparar nombres sin depender de mayúsculas.
5. **Línea 5:** detiene el recorrido si algún componente de la ruta está dentro de `SOR` o `Boveda_SOR`.
6. **Línea 6:** acepta solo la raíz física `SOR_Shell_Casa`; desde otra carpeta se para.
7. **Línea 7:** detiene el recorrido si esta raíz hereda un repositorio Git.
8. **Línea 8:** comprueba que existe la carpeta `VMs` dentro de esta raíz.

Si algo falla, **no abras el asistente ni crees la VM**; vuelve al README de este contexto.

> [!example] Paso 1 — Mide los recursos del anfitrión (**WINDOWS**)
> - **1A.** Abre **Inicio → Configuración → Sistema → Información**. En la tabla **«Recursos del ordenador y de ShellLab_Casa»** de tu nota, rellena las filas «Tipo de sistema de Windows» y «RAM instalada». El tipo de sistema permite saber si corresponde una ISO de 64 bits.
> - **1B.** Abre el **Explorador de archivos → Este equipo**. Mira el espacio libre de la unidad donde VirtualBox guardará la VM y rellena la fila «Espacio libre en la unidad de la VM» de **esa misma tabla**. No uses el espacio de otra unidad.
> - **1C.** Comprueba que VirtualBox se abre. Si no abre o no puedes ver arquitectura, RAM o espacio, anota lo ocurrido y consulta antes de seguir. **No cambies ajustes de firmware, Windows ni políticas del centro**.

> [!example] Paso 2 — Decide cuántos recursos puede usar `ShellLab_Casa` (**WINDOWS**)
> - **2A.** Si el equipo lo permite, toma como punto de partida **2048 MB de RAM, 2 procesadores y 25 GB de disco dinámico**. Son valores orientativos; si tu equipo no los admite, consulta antes de decidir.
> - **2B.** Vuelve a la tabla **«Recursos del ordenador y de ShellLab_Casa»** de tu nota. En «RAM para ShellLab_Casa», escribe la memoria que piensas asignar a la VM.
> - **2C.** Calcula «RAM que quedará para Windows»: a la RAM instalada del Paso 1 réstale la RAM elegida para ShellLab_Casa. Usa la misma unidad en las dos cantidades; para esta cuenta, 1 GB son 1024 MB. Escribe el resultado en su fila.
> - **2D.** Rellena «Procesadores para ShellLab_Casa» y «Tamaño máximo del disco virtual» con los valores que piensas configurar. En la tercera columna explica por qué Windows conserva memoria y espacio suficientes. Usa tus datos reales; no copies los de otro equipo.
> - **2E.** Comprueba el espacio libre antes de crear la VM. El disco virtual tendrá un máximo de 25 GB; con una instantánea, reserva como referencia conservadora 25 GB para el disco base + hasta 25 GB para los cambios de la instantánea + el tamaño exacto de la ISO que descargaste. Si la unidad no tiene ese espacio libre, detente y consulta; no reduzcas las cifras ni borres archivos por tu cuenta. Este análisis inicial es la evidencia de **CE.01.a**.

> [!example] Paso 3 — Crea `ShellLab_Casa` con la ISO comprobada (**WINDOWS, VirtualBox**)

Si no localizas esa opción, detente y contrasta la pantalla con el [manual de tu versión de VirtualBox](https://docs.oracle.com/en/virtualization/virtualbox/7.2/user/create-vm.html); no aceptes la creación a ciegas. Bajo «F0.2 · Máquina virtual» de tu nota, explica por qué elegiste el modo manual (**CE.01.b**).
> - **3D.** Comprueba que el sistema elegido es **Linux → Ubuntu de 64 bits**. Aplica la RAM y los procesadores justificados en el Paso 2.

> [!example] Paso 4 — Comprueba la red inicial (**WINDOWS, VirtualBox**)
