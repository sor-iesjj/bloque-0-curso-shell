## Qué necesitas entender antes de empezar

- **Máquina virtual (VM):** ordenador simulado por un programa. Tendrá memoria, procesadores y disco propios, aunque se ejecutará dentro del ordenador de Windows.
- **VirtualBox:** el programa que crea y ejecuta esa VM. La ventana de VirtualBox muestra y configura la máquina de pruebas.
- **Anfitrión:** el ordenador físico con Windows. **Invitado:** Ubuntu, que instalarás dentro de la VM.
- **Disco virtual dinámico:** archivo guardado en Windows que Ubuntu verá como su disco. El tamaño elegido es un *límite máximo*: el archivo crecerá conforme Ubuntu guarde datos. La ISO y las instantáneas también ocupan espacio en Windows.
- **NAT:** ajuste de VirtualBox que permite a la VM salir a Internet por la conexión del anfitrión. No tendrás que conocer ni modificar la dirección de la red del centro.
- **Instalación manual y desatendida:** en la manual contestarás las pantallas del instalador; en la desatendida VirtualBox puede contestarlas automáticamente. Elegimos **manual** porque aquí debes ver y justificar esas decisiones. [Manual oficial de VirtualBox](https://docs.oracle.com/en/virtualization/virtualbox/7.2/user/create-vm.html).

## Comprueba que este ordenador puede ejecutar VirtualBox

Esta guía se ha escrito para un **PC con Windows en un equipo x86-64**. VirtualBox publica instaladores oficiales para Windows; la compatibilidad depende del modelo del equipo, de la virtualización habilitada y de las políticas de administración. Un equipo ARM no debe tratarse como si fuera x86-64. Si Windows indica ARM, el instalador no ofrece el paquete adecuado, el equipo está gestionado y no tienes permiso de instalación, o VirtualBox no puede arrancar una VM de 64 bits, **detente y consulta**; no cambies BIOS/UEFI ni políticas del equipo.

1. En Windows abre **Configuración → Sistema → Acerca de** y comprueba «Tipo de sistema». Debe indicar sistema de 64 bits y procesador x64.
2. En el Administrador de tareas abre **Rendimiento → CPU** y localiza «Virtualización». Si aparece «Deshabilitada», detente y consulta al profesor; no cambies firmware por tu cuenta.
3. Comprueba si VirtualBox ya está instalado. Si no está y trabajas en Casa, descarga el instalador solo desde [VirtualBox Downloads](https://www.virtualbox.org/wiki/Downloads), selecciona el paquete Windows adecuado a tu arquitectura y sigue el asistente con una cuenta autorizada. Si el instalador pide permisos que no tienes, cancela y consulta. En un equipo del centro, no instales nada sin indicación del profesor o del administrador.
4. Abre VirtualBox y comprueba que llega a la ventana principal. Anota versión, tipo de sistema, estado de virtualización y cualquier bloqueo real en la nota.

No se presupone que todos los ordenadores puedan ejecutar la VM. Si el equipo no cumple, la práctica queda detenida hasta que el profesor asigne un equipo compatible; no se sustituye por una configuración improvisada. Consulta también el [manual de usuario de VirtualBox](https://www.virtualbox.org/manual/UserManual.html).

## Comprueba la ruta del disco virtual antes de abrir el asistente

Cierra cualquier asistente de creación que esté abierto. Desde Git Bash, sitúate en la raíz física `SOR_Shell_Casa` y ejecuta primero estas comprobaciones:

```bash
pwd -P
P=$(pwd -P)
N=$(printf '%s' "$P" | tr '[:upper:]' '[:lower:]')
case "$N" in */sor|*/sor/*|*/boveda_sor|*/boveda_sor/*) echo "PARADA: ancestro SOR"; exit 1;; esac
if git rev-parse --show-toplevel >/dev/null 2>&1; then echo "PARADA: hay un repositorio heredado"; exit 1; fi
test -d VMs
```

`pwd -P` enseña la ruta física; `N` normaliza mayúsculas; `case` detiene dentro del SOR o `Boveda_SOR`; `git rev-parse` detecta un repositorio heredado y `test -d VMs` confirma que existe el directorio elegido. Si cualquier comprobación falla, **no abras el asistente ni crees la VM**; vuelve al README de este recorrido.

> [!example] Paso 2 — Decide cuántos recursos puede usar `ShellLab_Casa` (**WINDOWS**)
> - **2A.** Si el equipo lo permite, toma como punto de partida **2048 MB de RAM, 2 procesadores y 25 GB de disco dinámico**. Son valores orientativos; si tu equipo no los admite, consulta antes de decidir.

> - **2C.** Calcula «RAM que quedará para Windows»: a la RAM instalada del Paso 1 réstale la RAM elegida para ShellLab_Casa. Usa la misma unidad en las dos cantidades; para esta cuenta, 1 GB son 1024 MB. Escribe el resultado en su fila.
> - **2D.** Rellena «Procesadores para ShellLab_Casa» y «Tamaño máximo del disco virtual» con los valores que piensas configurar. En la tercera columna explica por qué Windows conserva memoria y espacio suficientes. Usa tus datos reales; no copies los de otro equipo.
> - **2E.** Ten en cuenta que el disco dinámico, la ISO y las instantáneas ocupan espacio real. Si los recursos son insuficientes o no sabes decidir, consulta con el profesor antes de crear la VM. Este análisis inicial es la evidencia de **CE.01.a**.
