## 📚 Fundamento

> [!info] 📍 Punto de partida — de dónde vienes
> Este ejercicio **continúa el anterior**. Antes de empezar, comprueba que el escenario sigue en pie:
> ```
> ls -ld /srv/lab/facturacion && getfacl -p /srv/lab/facturacion | head -8
> id ana ; id toru ; id masao
> ```
>
> **Si algo falta** —porque partiste la fase en dos sesiones, te saltaste un ejercicio o restauraste una instantánea— reconstrúyelo en diez segundos:
> ```
> sudo groupadd -f facturacion ; sudo groupadd -f contabilidad ; sudo groupadd -f comercial
> id ana   >/dev/null 2>&1 || sudo useradd -m ana
> id toru  >/dev/null 2>&1 || sudo useradd -m toru
> id masao >/dev/null 2>&1 || sudo useradd -m masao
> sudo usermod -aG facturacion ana ; sudo usermod -aG contabilidad toru ; sudo usermod -aG comercial masao
> sudo mkdir -p /srv/lab/facturacion && sudo chgrp facturacion /srv/lab/facturacion && sudo chmod 2770 /srv/lab/facturacion
> ```

> [!info] Antes de empezar: la línea desmontada
> ```
> sudo setfacl -m g:contabilidad:rwx /srv/lab/facturacion
>               │  │      │      └── el permiso
>               │  │      └── a quién: el grupo
>               │  └── g = grupo   (u = usuario, m = máscara, o = otros)
>               └── -m = modify: añade o cambia esta entrada
> ```
>
> `-m` no borra nada: **añade** una entrada nueva o **cambia** la que hubiera para ese mismo destinatario.
>
> Los permisos se escriben pegados, sin guiones: **`rwx`**, **`rx`**, **`r`**. No `r-x`. *(Lo que `getfacl` te devuelve sí lleva guiones: `r-x`. Se lee con guiones y se escribe sin ellos. Es así y punto.)*
>
> Y hay dos tipos de destinatario:
>
> ```
> sudo setfacl -m u:ana:rwx /ruta          # a un USUARIO concreto
> sudo setfacl -m g:comercial:rx /ruta     # a un GRUPO
> ```
>
> Un aviso que ahorra horas: en carpetas, **lectura es `rx`, no `r`**. Sin la `x` no se puede entrar, así que la `r` no sirve de nada. Por eso toda la matriz de Boochan usa `rx`.

> [!tip] Idea clave
> `chmod` es **cambiar la cerradura**. `setfacl -m` es **añadir un nombre a la lista de la entrada**. La cerradura sigue igual; simplemente hay más gente autorizada, cada una con lo suyo.

> [!warning] El error nº1: dar `r` en vez de `rx` a una carpeta
> ```
> sudo setfacl -m g:comercial:r /srv/lab/facturacion
> ```
>
> Comercial puede **listar** los nombres… y no puede entrar, así que no abre nada. Y tú ves la entrada en `getfacl`, correcta, y no entiendes la queja.
>
> **En carpetas, lectura es `rx`.** Mira la matriz de la Fase 7 de Boochan: `r-x`, `r-x`, `r-x`, ocho veces. Ninguna es `r--`.
>
> Y esto ya lo demostraste en el `EJ-02-02-01`, con `chmod 754`. Es el mismo concepto, en otra herramienta.

> [!example] Vocabulario de esta práctica
> - **`setfacl -m`:** *modify*: añade o cambia una entrada.
> - **`g:grupo:permisos`:** entrada para un grupo.
> - **`u:usuario:permisos`:** entrada para un usuario concreto.
> - **Entrada extra:** la que tiene nombre. La que rompe el límite del grupo único.
> - **`+` en `ls -l`:** la marca de que un fichero tiene ACL. `drwxrwx---+`

> [!info] 🔗 Dónde lo vas a usar
> Es **el comando de la Fase 7 de Boochan**: `sudo setfacl -m g:comercial:rx /srv/samba/departamentos/rrhh`, repetido ocho veces con la matriz completa. Cuando llegues allí, esta línea ya no será magia.

> getfacl -p /srv/lab/facturacion
> sudo -u toru ls /srv/lab/facturacion
> sudo -u masao ls /srv/lab/facturacion
> ```
>
> Toru y masao, fuera. Vamos a resolverlo bien esta vez.

> [!example] Paso 2 — Da escritura a contabilidad
> ```
> sudo setfacl -m g:contabilidad:rwx /srv/lab/facturacion
> getfacl -p /srv/lab/facturacion
> ```
>
> Mira la salida: hay una línea nueva, `group:contabilidad:rwx`. **Y también ha aparecido `mask::rwx`**, que antes no estaba. Ignórala de momento: es el `EJ-06-03-01` entero.
>
> Compruébalo:
>
> ```
> sudo -u toru touch /srv/lab/facturacion/apunte-toru.txt

> ```
>
> Toru escribe. **Y ana no ha perdido nada.**

> [!example] Paso 3 — Fíjate en el `+` de `ls -l`
> ```
> ls -ld /srv/lab/facturacion
> ```
>
> Ahora acaba en **`+`**: `drwxrws---+`.
>
> Ese `+` significa *"aquí hay ACL, mira con `getfacl` si quieres saber la verdad"*. Es la señal de que `ls -l` **ya no te cuenta toda la historia**.
>
> Apréndetela: es la pista de que hay más permisos de los que ves.

> [!example] Paso 4 — Da lectura a comercial (y hazlo mal primero)
> ```
> sudo setfacl -m g:comercial:r /srv/lab/facturacion
> getfacl -p /srv/lab/facturacion | grep comercial
>
> sudo -u masao ls /srv/lab/facturacion
> sudo -u masao cat /srv/lab/facturacion/apunte-toru.txt
> ```
>
> `ls` funciona, `cat` **falla**. Ahí tienes el error nº1: le falta la `x`.
>
> Arréglalo:
>
> ```
> sudo setfacl -m g:comercial:rx /srv/lab/facturacion
> sudo -u masao ls /srv/lab/facturacion
> sudo -u masao cat /srv/lab/facturacion/apunte-toru.txt
> ```

> [!example] Paso 5 — Comprueba que comercial NO escribe
> ```
> sudo -u masao touch /srv/lab/facturacion/masao.txt
> sudo -u masao rm /srv/lab/facturacion/apunte-toru.txt
> ```
>
> Los dos fallan. **Esta es la prueba que valida el trabajo**, no la anterior.
>
> Lucía tenía tres requisitos y ya están los tres. Con permisos clásicos era imposible; con una lista, son dos comandos.

> [!example] Paso 6 — Prueba también con un usuario concreto
> ```
> id auditora >/dev/null 2>&1 || sudo useradd -m auditora
> sudo setfacl -m u:auditora:rx /srv/lab/facturacion
> getfacl -p /srv/lab/facturacion
> sudo -u auditora ls /srv/lab/facturacion
> sudo -u auditora touch /srv/lab/facturacion/x.txt
> ```
>
> Una persona concreta, sin crear un grupo para ella. Útil para accesos puntuales — **y peligroso si se olvidan ahí**: un usuario suelto en una ACL es de las cosas que nadie revisa nunca.

## 🚩 Errores y verificación

> [!warning] Errores típicos (evítalos)
> | Error | Qué pasa | Cómo evitarlo |
> | :--- | :--- | :--- |
> | Dar `r` en vez de `rx` a una carpeta | Listan los nombres pero no abren nada | En carpetas, lectura es `rx`. |
> | Escribir los permisos con guiones (`r-x`) | `setfacl` no lo entiende | Se escribe `rx`; `getfacl` los devuelve con guiones. |
> | No fijarse en el `+` de `ls -l` | Crees que `ls -l` te cuenta toda la verdad | El `+` avisa de que hay ACL. |
> | Dejar entradas de usuario suelto para siempre | Accesos que nadie revisa | Prefiere grupos. Y audita periódicamente. |

> [!success] ✅ Verificación: ¿está bien hecho?
> - `getfacl -p` muestra `group:contabilidad:rwx` y `group:comercial:r-x`.
> - `ls -ld` acaba en `+`.
> - Toru escribe, masao lee y masao **no** puede escribir.
> - Has visto fallar `cat` con permiso `r` y funcionar con `rx`.
