## EJ-01-01-01 — Marko comprueba su laboratorio y saca un archivo de prueba

> [!abstract] Ficha de la práctica
> - **Fase 1 · Nivel N1.** La VM `ShellLab` con Ubuntu Server **ya se instaló en la Fase 0**. Aquí no se instala otra vez.
> - **Preparación para RA.01:** aprendes a distinguir el ordenador Windows de la sesión de Ubuntu y a trasladar una prueba sin compartir la bóveda. Esta práctica por sí sola no acredita un CE nuevo de RA.01.
> - **Entrada:** `shell-1.1.1-prueba-el-acceso-ssh.md` en `00_Apuntes/Trimestre_1/B0_Curso_Shell/`.
> - **Vídeo:** `B0.S.1.1.1 · Marko prueba el acceso SSH` en `B0_Curso_Shell`, como «No listado».

> [!info] Situación
> Marko ya puede entrar en su Ubuntu de pruebas. Lucía le pide que demuestre dos cosas antes de darle trabajos reales: que sabe **en qué ordenador ejecuta cada comando** y que puede sacar un archivo de la VM sin darle acceso a sus apuntes.

## Fundamento: dos sesiones y una copia

- **Git Bash local:** ventana del ordenador Windows. Antes de conectar y después de `exit`, los comandos actúan aquí.
- **Sesión SSH:** desde Git Bash ves una terminal de Ubuntu; los comandos actúan en `ShellLab` hasta `exit`.
- **`scp`:** copia un archivo a través de SSH. Usaremos la misma regla de VirtualBox que probaste en F0.4. En `scp`, la opción del puerto es **`-P` mayúscula**; en `ssh` es **`-p` minúscula**.
- **Carpeta temporal:** un lugar de Windows para recibir archivos de prueba. Debe estar **fuera** de `Boveda_SOR`. No configuraremos carpetas compartidas de VirtualBox ni instalaremos Guest Additions para copiar este archivo.

## Antes de grabar

1. Lee todos los pasos, incluida la entrega. Comprueba que terminaste la [Fase 0](../fase-0-preparar-laboratorio/README.md), que `ShellLab` arranca y que ves la instantánea `ShellLab - SSH operativo`.
2. En Obsidian abre **antes de trabajar** la entrada vacía `00_Apuntes/Trimestre_1/B0_Curso_Shell/shell-1.1.1-prueba-el-acceso-ssh.md` con la [plantilla del curso](../02_ENTREGABLES.md).
3. Ten a mano OBS y tu identidad. El vídeo se llamará **`B0.S.1.1.1 · Marko prueba el acceso SSH`**, irá en **`B0_Curso_Shell`** y será **«No listado»**.
4. Ten anotado el puerto anfitrión real de F0.4. En los comandos aparece `2222`: si usaste otro, cámbialo **en `ssh` y en `scp`**.

## Procedimiento

> [!example] Paso 0 — Abre tus apuntes y empieza la grabación (**WINDOWS**)
> - **0A.** Inicia OBS, preséntate y muestra tu identidad.
> - **0B.** Explica que comprobarás la conexión y copiarás un archivo de prueba de Ubuntu a Windows.
> - **0C.** Muestra la entrada vacía. Anota los resultados mientras trabajas, sin escribir la contraseña.

> [!example] Paso 1 — Arranca y conecta (**WINDOWS → VM**)
> - **1A.** Abre VirtualBox y arranca `ShellLab`. Espera a que Ubuntu muestre `login:`; no necesitas escribir ahí tu contraseña si SSH funciona.
> - **1B.** Abre Git Bash en Windows y conecta:
>
> ```bash
> ssh -p 2222 marko@127.0.0.1
> ```
>
> - **1C.** `-p` selecciona el puerto de Windows que configuraste en F0.4; `marko` es el usuario de Ubuntu. Introduce la contraseña cuando se pida; no se mostrará en pantalla. Si no conecta, vuelve a [F0.4, «Si no conecta»](../fase-0-preparar-laboratorio/F0-04_SSH.md#si-no-conecta). No continúes ejecutando comandos Linux en Git Bash local.

> [!example] Paso 2 — Comprueba dónde estás y crea la prueba (**VM por SSH**)
> - **2A.** Ejecuta `whoami`, `hostname` y `pwd`, uno por uno. Debes reconocer a `marko`, `shelllab` y la carpeta personal de Ubuntu.
> - **2B.** Crea un archivo de texto **en Ubuntu** y comprueba su contenido:
>
> ```bash
> printf 'Prueba desde ShellLab\n' > /home/marko/prueba-shelllab.txt
> cat /home/marko/prueba-shelllab.txt
> ```
>
> - **2C.** `printf` genera el texto; `>` lo guarda en el archivo indicado; `cat` lo lee. Anota qué mostró `cat`. El archivo sigue dentro de la VM: todavía no está en Windows.
> - **2D.** Escribe `exit` y pulsa `Enter`. Has cerrado SSH; ahora Git Bash vuelve a ejecutar comandos **en Windows**.

> [!example] Paso 3 — Prepara el destino separado (**WINDOWS**)
> - **3A.** En el Explorador, localiza `Boveda_SOR`. Abre la carpeta **que la contiene** y crea al mismo nivel una carpeta `Intercambio_Shell`. No la crees dentro de la bóveda ni en un repositorio.
> - **3B.** Entra en `Intercambio_Shell`. En la barra de direcciones comprueba que `Intercambio_Shell` y `Boveda_SOR` aparecen como carpetas hermanas. Si `Intercambio_Shell` está dentro de `Boveda_SOR`, detente y corrige la ubicación **antes de copiar**.
> - **3C.** Abre **Git Bash en `Intercambio_Shell`** y ejecuta `pwd`. Lee la ruta: debe terminar en `Intercambio_Shell`, **fuera de la bóveda**. Si no es así, no ejecutes `scp`.

> [!example] Paso 4 — Copia por SSH (**WINDOWS, Git Bash dentro de `Intercambio_Shell`**)
> - **4A.** Ejecuta, cambiando `2222` solo si el puerto real es otro:
>
> ```bash
> scp -P 2222 marko@127.0.0.1:/home/marko/prueba-shelllab.txt .
> ```
>
> - **4B.** `scp` copia por SSH; `-P 2222` indica el puerto del anfitrión; antes de `:` está el usuario y destino remoto; después de `:` está la ruta **dentro de Ubuntu**; el punto final `.` significa «en esta carpeta de Windows». Cuando pida la contraseña, usa la de `marko`.
> - **4C.** Comprueba la copia desde Git Bash local con `ls` y `cat prueba-shelllab.txt`. Abre también `Intercambio_Shell` en el Explorador. El archivo debe verse y leerse en Windows. Anota la prueba en tus apuntes. No necesitas subir este archivo de prueba al repositorio.

> [!example] Paso 5 — Cierra y entrega (**WINDOWS**)
> - **5A.** Detén OBS. Sube el vídeo con el título **`B0.S.1.1.1 · Marko prueba el acceso SSH`** a **`B0_Curso_Shell`**, como **«No listado»**. Añade `00:00 Presentación` y una marca por cada paso en la descripción; pega el enlace en la entrada.
> - **5B.** En Git Bash abierto **en la raíz de `apuntes-sor-t1`** comprueba `pwd` y `git status`. Luego prepara **solo** la entrada:
>
> ```bash
> git add B0_Curso_Shell/shell-1.1.1-prueba-el-acceso-ssh.md
> git diff --cached --stat
> git commit -m "Curso Shell: EJ-01-01-01 terminado"
> git push
> ```
>
> - **5C.** `git diff --cached --stat` debe mostrar la entrada y no otros archivos. Comprueba en GitHub que la entrada y el enlace del vídeo aparecen. Entrega el enlace del repositorio por la tarea de Teams.

## Errores y verificación

| Si ocurre esto | Qué comprobar |
| :--- | :--- |
| Ejecutas `printf` y `hostname` no dice `shelllab` | No estás dentro de la sesión SSH; vuelve al Paso 1. |
| `scp` muestra «No such file» | Revisa que el archivo exista en `/home/marko/` dentro de Ubuntu y que no escribiste mal su nombre. |
| El archivo se copia dentro de la bóveda | Detente: la carpeta temporal debe estar fuera; revisa `pwd` antes de repetir. |
| `scp` pide otra vez contraseña | Es la contraseña del usuario Ubuntu; revisa también que `-P` lleva mayúscula. |

> [!question] Responde en tus apuntes
> ¿Qué cambia exactamente después de `exit`? ¿Por qué `scp` lleva `-P` mayúscula y un punto final? ¿Por qué comprobaste `pwd` antes de copiar?
