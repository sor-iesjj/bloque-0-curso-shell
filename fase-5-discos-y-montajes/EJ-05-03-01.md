## 📚 Fundamento

> [!info] Antes de empezar: los seis campos y el comando que te salva
> Cada línea de `/etc/fstab` tiene **seis campos separados por espacios**:
>
> ```
> /samba_deptos.img  /srv/samba/departamentos  ext4  loop,defaults  0  0
>        1                      2                3         4        5  6
> ```
>
> 1. **Qué se monta** — el dispositivo, la imagen o el UUID
> 2. **Dónde** — el punto de montaje (tiene que existir)
> 3. **Tipo** — `ext4`, `vfat`, `xfs`…
> 4. **Opciones** — `defaults`, `loop`, `ro`, `noauto`…
> 5. **dump** — copias de seguridad. Casi siempre `0`
> 6. **fsck** — orden de revisión al arrancar. `0` = no revisar, `1` = raíz, `2` = los demás
>
> Y el comando que evita todos los desastres:
>
> ```
> sudo mount -a
> ```
>
> **Monta todo lo declarado en `fstab` que no esté montado ya.** Si tu línea está mal, `mount -a` te lo dice **ahora**, con la máquina arrancada y tú delante. Si no lo pruebas y reinicias, te lo dice el sistema de arranque, en modo emergencia.
>
> Y el aviso de systemd que verás:
>
> ```
> your fstab has been modified, but systemd still uses the old version;
> use 'systemctl daemon-reload' to reload.
> ```
>
> No es un error: es systemd pidiéndote que relea el fichero.

> [!tip] Idea clave
> `/etc/fstab` es **la lista de tareas del arranque**. Si escribes una tarea imposible, el sistema no la salta: se planta y espera. Por eso `mount -a` es el **ensayo general**: pruebas la lista con las luces encendidas antes de la función.

> [!warning] El error nº1: editar `fstab` y reiniciar sin probar con `mount -a`
> Si hay un error, el sistema arranca en **modo emergencia**:
>
> ```
> You are in emergency mode
> Give root password for maintenance
> ```
>
> Con la contraseña de root sales; **sin ella, no entras en tu propio servidor**. Y en una máquina remota, sin consola física, esto es una llamada al proveedor.
>
> Los tres pasos, y no se salta ninguno:
>
> 1. `sudo cp /etc/fstab /etc/fstab.bak`
> 2. editar
> 3. **`sudo mount -a`** — si no dice nada, está bien
>
> Solo entonces reinicias.

> [!example] Vocabulario de esta práctica
> - **`/etc/fstab`:** la tabla de sistemas de ficheros que se montan al arrancar.
> - **`mount -a`:** monta todo lo de `fstab` que falte. **El ensayo general**.
> - **`defaults`:** el conjunto de opciones habitual (lectura/escritura, etc.).
> - **`loop`:** obligatoria para montar un fichero imagen.
> - **Modo emergencia:** el sistema no ha podido montar algo de `fstab` y se detiene.

> [!example] Paso 2 — Prepara lo que vas a montar
> Si vienes del ejercicio anterior ya lo tienes. Si no:

> ```
> sudo dd if=/dev/zero of=/lab-deptos.img bs=1M count=300
> sudo mkfs.ext4 /lab-deptos.img
> sudo mkdir -p /srv/lab/departamentos
> sudo umount /srv/lab/departamentos 2>/dev/null
> ```

> [!example] Paso 3 — Escribe la línea
> ```
> sudo nano /etc/fstab
> ```
>
> Añade al final, **exactamente**:
>
> ```
> /lab-deptos.img  /srv/lab/departamentos  ext4  loop,defaults  0  0
> ```
>
> Guarda (`Ctrl`+`O`, Enter) y sal (`Ctrl`+`X`).
>
> Compruébalo:
>
> ```
> tail -3 /etc/fstab
> diff /etc/fstab.bak /etc/fstab
> ```
>
> Repasa los seis campos de tu línea uno a uno, en voz alta, antes de seguir.

> [!example] Paso 4 — El ensayo general
> ```
> sudo mount -a
> ```
>
> **Si no dice nada, está bien.** Silencio es aprobado.
>
> Puede que te salga el aviso de systemd:
>
> ```
> sudo systemctl daemon-reload
> sudo mount -a
> ```
>
> Y verifica:
>
> ```
> mountpoint /srv/lab/departamentos
> df -h /srv/lab/departamentos
> findmnt /srv/lab/departamentos
> ```

> [!example] Paso 5 — Ahora sí, el reinicio
> ```
> sudo touch /srv/lab/departamentos/prueba-persistencia.txt
> sudo reboot
> ```
>
> Al volver:
>
> ```
> mountpoint /srv/lab/departamentos
> ls -l /srv/lab/departamentos
> df -h /srv/lab/departamentos
> ```
>
> **Montado solo.** Ese es el objetivo de todo el ejercicio.

> [!example] Paso 6 — Comprueba qué pasa si el punto de montaje no existe
> ```
> sudo cp /etc/fstab /etc/fstab.bak2
> echo "/lab-deptos.img  /srv/lab/inexistente  ext4  loop,defaults  0  0" | sudo tee -a /etc/fstab > /dev/null
> sudo mount -a
> ```
>
> Error: `mount point does not exist`. **Y lo has descubierto con `mount -a`, no reiniciando.**
>
> Ese es el valor del ensayo general: el mismo error que te habría dejado en modo emergencia, aquí es una línea roja en pantalla y sigues trabajando.
>
> ```
> sudo cp /etc/fstab.bak2 /etc/fstab
> sudo mount -a
> sudo rm -f /etc/fstab.bak2
> ```

> [!example] Paso 7 — Deja el sistema como estaba
> ```
> sudo umount /srv/lab/departamentos
> sudo cp /etc/fstab.bak /etc/fstab

## 🚩 Errores y verificación

> [!warning] Errores típicos (evítalos)
> | Error | Qué pasa | Cómo evitarlo |
> | :--- | :--- | :--- |
> | Editar `fstab` y reiniciar sin `mount -a` | Modo emergencia | `mount -a` siempre antes de reiniciar. |
> | Punto de montaje inexistente | `mount point does not exist` | `mkdir -p` antes. |
> | Olvidar la opción `loop` con una imagen | El montaje falla | `loop,defaults` para ficheros. |
> | No hacer copia de `fstab` | No tienes vuelta atrás si la lías | `cp /etc/fstab /etc/fstab.bak` antes de abrir el editor. |

> [!success] ✅ Verificación: ¿está bien hecho?
> - `sudo mount -a` no devuelve nada.
> - Tras el reinicio, `mountpoint` confirma que se montó solo.
> - El fichero de prueba sigue ahí tras el reinicio.
> - Has visto `mount -a` detectar un error que te habría dejado en emergencia.
