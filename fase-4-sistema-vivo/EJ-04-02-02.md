> [!info] Situación
> Lucía: *"Este servidor viene de otro cliente y tenía Samba instalado con una configuración que no conocemos. Quítalo del todo antes de empezar. Del todo, Marko. No quiero encontrarme mañana un fichero de configuración viejo mandando sobre el nuevo."*

- **🎯 Objetivo real:** instalar, consultar y **eliminar completamente** paquetes, distinguiendo `remove` de `purge`.
- **🧩 Problema que resuelve:** desinstalar mal deja **la configuración vieja** en el disco. Y cuando reinstalas, el paquete la reutiliza. Es el origen de fallos imposibles de explicar.

## 📚 Fundamento

> [!info] Antes de empezar: cuatro verbos y una diferencia crítica
> | Comando | Qué hace |
> | :--- | :--- |
> | `sudo apt update` | actualiza **la lista** de paquetes disponibles. No instala nada |
> | `sudo apt upgrade -y` | actualiza los paquetes ya instalados |
> | `sudo apt install -y paquete` | instala |
> | `sudo apt remove paquete` | desinstala **pero deja la configuración** |
> | `sudo apt purge paquete` | desinstala **y borra su configuración** |
> | `sudo apt autoremove -y` | quita dependencias que ya no usa nadie |
>
> Esa diferencia entre `remove` y `purge` es la del enunciado. `remove` deja los ficheros de `/etc` del paquete. `purge` los borra.
>
> Y para consultar, `dpkg`:
>
> | Comando | Qué te dice |
> | :--- | :--- |
> | `dpkg -s paquete` | el estado: instalado, configurado, o no |
> | `dpkg -l \| grep algo` | lista los que coincidan |
> | `dpkg --audit` | paquetes a medio instalar. **Sin salida = todo bien** |
> | `apt list --upgradable` | qué queda por actualizar |
>
> **`apt update` no actualiza nada.** Solo consulta el catálogo. Es el malentendido más repetido del mundo Debian.

> [!tip] Idea clave
> `remove` es **echar al inquilino y dejarle los muebles en el piso**. `purge` es vaciar el piso. Si vuelves a alquilar sin vaciar, el inquilino nuevo se encuentra los muebles del anterior y se pregunta de quién es ese sofá.

> [!warning] El error nº1: `apt remove` cuando querías `purge`, y reinstalar encima
> Desinstalas Samba con `remove`, lo reinstalas, y arrastra la configuración del cliente anterior. El servicio arranca con opciones que tú no has puesto y que no aparecen en ninguna documentación tuya.
>
> La **Fase 2 de Boochan** está construida precisamente sobre esto: purga explícita con lista de paquetes, `autoremove`, y encima `sudo rm -rf /etc/samba/ /var/lib/samba/` para los residuos que `purge` no se lleva.
>
> Y otro aviso de ahí: **nada de comodines**. `apt purge samba*` puede arrastrar paquetes que no querías. Lista explícita, siempre.

> [!example] Vocabulario de esta práctica
> - **`apt update`:** refresca el catálogo. **No instala nada**.
> - **`apt purge`:** desinstala **y borra la configuración**.
> - **`apt autoremove`:** quita las dependencias huérfanas.
> - **`dpkg -s`:** el estado exacto de un paquete.
> - **`dpkg --audit`:** paquetes a medio instalar. Sin salida = todo correcto.

> [!info] 🔗 Dónde lo vas a usar
> **Fase 2 de Boochan** entera: `sudo apt purge -y samba samba-common samba-common-bin winbind …`, `sudo apt autoremove -y`, `dpkg -l | grep -E '^ii\s+samba'` para comprobar que no queda nada, y `sudo dpkg --audit`. Y **Fase 7**: `sudo apt install -y acl`, sin el cual `setfacl` ni existe.

> [!example] Paso 1 — Comprueba que `update` no instala
> ```
> sudo apt update
> apt list --upgradable
> ```
>
> `update` ha hablado con los repositorios y te dice qué **podría** actualizarse. No ha tocado nada.
>
> Dilo en voz alta: es el malentendido más repetido.

> [!example] Paso 2 — Instala algo y consúltalo bien
> ```
> sudo apt install -y tree
> which tree
> dpkg -s tree
> dpkg -s tree | grep -m1 ^Status
> ```
>
> `Status: install ok installed`. Ese `grep -m1 ^Status` es exactamente lo que hace la Fase 2 de Boochan para comprobar paquete a paquete.
>
> Pruébalo:
>
> ```
> tree ~ -L 2
> ```

> [!example] Paso 3 — Crea una configuración y prueba `remove`
> ```
> sudo mkdir -p /etc/tree.d
> echo "opcion=valor" | sudo tee /etc/tree.d/config.conf > /dev/null
>
> sudo apt remove -y tree
> which tree
> ls -l /etc/tree.d/
> ```
>
> El programa se ha ido. **La configuración sigue ahí.** Eso es `remove`.
>
> *(He usado una carpeta de ejemplo porque `tree` no trae configuración propia; el comportamiento con paquetes que sí la traen es el mismo.)*

> [!example] Paso 4 — Ahora con un paquete que sí tiene configuración
> ```
> sudo apt install -y vsftpd
> ls -l /etc/vsftpd.conf
> dpkg -s vsftpd | grep -m1 ^Status
>
> sudo apt remove -y vsftpd
> dpkg -s vsftpd | grep -m1 ^Status
> ls -l /etc/vsftpd.conf
> ```
>
> `Status: deinstall ok config-files`: **desinstalado pero con su configuración guardada**. Ahí está el fichero.
>
> Ahora la purga:
>
> ```
> sudo apt purge -y vsftpd
> dpkg -s vsftpd 2>&1 | head -2
> ls -l /etc/vsftpd.conf
> ```
>
> Ya no existe ni el paquete ni el fichero. **Esa es la diferencia** que pedía Lucía.

> [!example] Paso 5 — Limpia dependencias y audita
> ```
> sudo apt autoremove -y
> sudo dpkg --audit
> echo $?
> ```
>
> `dpkg --audit` **sin salida** significa que no hay ningún paquete a medias. Es la comprobación que hace la Fase 2 de Boochan antes de dar la purga por buena.

> [!example] Paso 6 — Comprueba que no queda rastro, como en Boochan
> ```
> dpkg -l | grep -E "^ii" | grep -i vsftpd
> dpkg -l | grep -E "^rc" | head -5
> ```
>
> - `ii` = instalado y configurado.
> - `rc` = **removido pero con configuración residual**. Justo lo que hay que evitar.
>
> Si ves algo en `rc` que no quieres, ahí tienes tu lista de purga pendiente. Este comando es oro puro en una máquina heredada.
>
> ```
> sudo rm -rf /etc/tree.d
> ```

## 🚩 Errores y verificación

> [!warning] Errores típicos (evítalos)
> | Error | Qué pasa | Cómo evitarlo |
> | :--- | :--- | :--- |
> | Creer que `apt update` actualiza el sistema | El sistema sigue igual y crees que ya está | `update` refresca el catálogo; `upgrade` actualiza. |
> | `remove` en vez de `purge` | La configuración vieja sobrevive y manda al reinstalar | `purge` cuando quieras eliminar de verdad. |
> | Usar comodines: `apt purge samba*` | Arrastras paquetes que no querías | Lista explícita, como hace Boochan. |
> | No comprobar `dpkg -l | grep ^rc` | Quedan residuos que reaparecen | Revísalo después de purgar. |

> [!success] ✅ Verificación: ¿está bien hecho?
> - Sabes explicar qué hace `apt update` y qué no.
> - Has visto `deinstall ok config-files` tras un `remove`.
> - Tras el `purge`, el fichero de `/etc` ya no existe.
> - `dpkg --audit` no devuelve nada.
