- **🎯 Objetivo real:** meter una secuencia de comandos en un fichero y ejecutarla como un programa.
- **🧩 Problema que resuelve:** lo que se repite a mano se ejecuta mal algún día: te saltas un comando, cambias el orden, o lo escribes con una errata. Un script hace **siempre exactamente lo mismo**.

## 📚 Fundamento

> [!info] Antes de empezar: tres cosas y ya tienes un script
> Un script no es más que **un fichero de texto con comandos**, uno por línea. Solo hace falta:
>
> **1. La primera línea, el *shebang*:**
>
> ```
> #!/bin/bash
> ```
>
> Le dice al sistema **con qué programa** hay que interpretar el fichero. Sin ella, el sistema adivina, y adivina mal.
>
> **2. Permiso de ejecución:**
>
> ```
> chmod +x miscript.sh
> ```
>
> Esto ya lo hiciste en el `EJ-02-03-02`. Ahora sabes para qué era.
>
> **3. Ejecutarlo con `./`:**
>
> ```
> ./miscript.sh
> ```
>
> Ese `./` significa *"el de esta carpeta"*. Sin él, el sistema busca `miscript.sh` en las carpetas del `PATH` —`/usr/bin`, `/bin`…— y no lo encuentra, aunque lo tengas delante.
>
> Y los comentarios, con `#`:
>
> ```
> # Esto no se ejecuta. Es para el humano que lo lea dentro de un año.
> ```

> [!tip] Idea clave
> Un script es **una receta escrita**. Cocinar de memoria funciona hasta el día que te distraes y te saltas el paso de la sal. La receta escrita sale igual siempre, la puede seguir otro, y si sale mal se puede revisar dónde estaba el fallo.

> [!warning] El error nº1: ejecutar el script sin `./`
> ```
> miscript.sh
> ```
>
> ```
> orden no encontrada
> ```
>
> Y lo tienes delante, en la misma carpeta. La shell solo busca programas en las carpetas del `PATH`, y **la carpeta actual no está en el `PATH`** a propósito, por seguridad: si lo estuviera, bastaría con dejar un fichero llamado `ls` en una carpeta para que ejecutaras el falso en vez del bueno.
>
> Por eso todos los verificadores de Boochan se lanzan así:
>
> ```
> sudo ./verificar_fase7.sh
> ```
>
> Ese `./` no es decoración.

> [!example] Vocabulario de esta práctica
> - **Script:** fichero de texto con comandos que se ejecutan en orden.
> - **Shebang (`#!/bin/bash`):** la primera línea: dice con qué intérprete ejecutarlo.
> - **`chmod +x`:** da permiso de ejecución. Sin esto, no arranca.
> - **`./`:** "el de esta carpeta". Necesario porque el directorio actual no está en el `PATH`.
> - **`PATH`:** la lista de carpetas donde la shell busca los programas.

> [!info] 🔗 Dónde lo vas a usar
> Es el gesto de arranque de **todas las fases de Boochan**: `curl -O …/verificar_fase7.sh`, `chmod +x verificar_fase7.sh`, `sudo ./verificar_fase7.sh`. Tres comandos que has ejecutado sin saber qué hacían. A partir de aquí, sí.

> [!example] Paso 2 — Escribe tu primer script
> ```
> cd ~
> nano comprobar.sh
> ```
>
> Dentro:
>
> ```
> #!/bin/bash
> # comprobar.sh - revision matinal del servidor
> # Marko - Boochan Networks S.L.
>
> echo "=== Comprobacion del servidor ==="
> date
> hostname
> uptime
> df -h /
> ```
>

> [!example] Paso 3 — Reproduce los dos errores clásicos
> ```
> comprobar.sh
> ```
>
> `orden no encontrada`. Falta el `./`.
>
> ```
> ./comprobar.sh
> ```
>
> `Permiso denegado`. Falta el `+x`.
>
> **Los dos errores en veinte segundos.** Ahora ya sabes reconocerlos.

> [!example] Paso 4 — Dale permisos y ejecútalo
> ```
> ls -l comprobar.sh
> chmod +x comprobar.sh
> ls -l comprobar.sh
> ./comprobar.sh
> ```
>
> Fíjate en el `ls -l` antes y después: han aparecido las tres `x`. Y ahora funciona.
>
> **Esto es exactamente lo que haces al principio de cada fase de Boochan.**

> [!example] Paso 5 — Comprueba para qué sirve el shebang
> ```
> cp comprobar.sh sin-shebang.sh
> sed -i '1d' sin-shebang.sh
> head -3 sin-shebang.sh
> chmod +x sin-shebang.sh
> ./sin-shebang.sh
> ```
>
> Puede que funcione igual: si tu shell es bash, hereda el intérprete. **Y ahí está el peligro**: funciona en tu máquina y falla en otra donde la shell sea distinta.
>
> El shebang quita esa lotería. Ponlo siempre.
>
> ```
> rm sin-shebang.sh
> ```

> [!example] Paso 6 — Comprueba que el script devuelve un resultado
> ```
> ./comprobar.sh > /dev/null
> echo $?
> ```
>
> `0`. El script ha terminado bien.
>
> Recuerda el `$?` del `EJ-03-01-02`: los scripts también devuelven código de salida, y en el `EJ-07-03-01` lo controlarás tú. El `verificar_fase7.sh` de Boochan acaba con `exit 0` si apruebas y `exit 1` si no.

## 🚩 Errores y verificación

> [!warning] Errores típicos (evítalos)
> | Error | Qué pasa | Cómo evitarlo |
> | :--- | :--- | :--- |
> | Ejecutar sin `./` | `orden no encontrada` aunque lo tengas delante | `./script.sh`. El directorio actual no está en el `PATH`. |
> | Olvidar `chmod +x` | `Permiso denegado` | `chmod +x script.sh`. |
> | Script sin shebang | Funciona en tu máquina y falla en otra | `#!/bin/bash` siempre en la primera línea. |
> | Script sin comentario de cabecera | Nadie sabe qué hace dentro de seis meses | Nombre, qué hace y cómo se usa, arriba del todo. |

> - El script tiene shebang y comentario de cabecera.
