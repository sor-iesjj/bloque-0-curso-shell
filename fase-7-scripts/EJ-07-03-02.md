## EJ-07-03-02 — Marko recorre una lista línea a línea: `while IFS= read -r`

> [!abstract] Ficha de la práctica
> ### 📌 `B0.S.7.3.2` — Marko recorre una lista línea a línea: `while IFS= read -r`
> - **Fase 7** (Leer y escribir un script de bash) · **Nivel 3** (Medio)
> - **🎬 Playlist:** `B0_Curso_Shell`
> - **📹 Nombre del vídeo:** `B0.S.7.3.2 · Marko recorre una lista linea a linea`

> [!info] Situación
> Lucía le pasa la matriz de permisos: quince líneas con el formato `carpeta:grupo:permiso`. Marko intenta meterla en un `for` y el bucle se le parte por donde no debe: cada palabra es una vuelta, no cada línea.

- **🎯 Objetivo real:** recorrer una lista **línea a línea**, aunque las líneas contengan espacios o caracteres raros.
- **🧩 Problema que resuelve:** `for` parte por **espacios**. Cuando cada elemento es una línea entera —una matriz de permisos, una lista de usuarios con nombre y apellido— hace falta otra herramienta.

> [!info] Antes de empezar: la línea que hay que saber leer
> ```
> while IFS= read -r LINEA; do
>     echo "[$LINEA]"
> done <<< "$CRUCES"
> ```
>
> Cuatro piezas, y cada una está ahí por una razón concreta:
>
> | Pieza | Qué hace | Qué pasa sin ella |
> | :--- | :--- | :--- |
> | `while` | repite mientras `read` tenga éxito | — |
> | `IFS=` | **vacía el separador de campos** | `read` recorta los espacios del principio y del final |
> | `read -r` | lee una línea en la variable | sin `-r`, la `\` se interpreta y se pierde |
> | `<<< "$VAR"` | le pasa el contenido de la variable como entrada | — |
>
> Ese `<<<` se llama **here-string**: convierte un texto en la entrada del bucle. Es primo del here-doc `<<'EOF'` que viste en el `EJ-03-03-02`.
>
> Y las otras dos formas de alimentarlo:
>
> ```
> while IFS= read -r LINEA; do ... done < fichero.txt        # desde un fichero
> comando | while IFS= read -r LINEA; do ... done            # desde una tubería
> ```
>
> `for` frente a `while read`, resumido:
>
> | | parte por | úsalo para |
> | :--- | :--- | :--- |
> | `for` | **espacios** | listas de palabras sueltas: nombres de departamento |
> | `while read` | **líneas** | líneas con estructura interna: `carpeta:grupo:permiso` |

> [!tip] Idea clave
> `for` es **repartir cartas de una baraja**: cada carta es una unidad y no tiene partes. `while read` es **leer un listado en papel renglón a renglón**: cada renglón es una unidad y dentro tiene columnas que luego separarás.

> [!warning] El error nº1: usar `for` sobre líneas con espacios
> ```
> USUARIOS="hiroshi.nohara:10001:Hiroshi Nohara
> misae.nohara:10003:Misae Nohara"
>
> for u in $USUARIOS; do echo "[$u]"; done
> ```
>
> Te salen **cuatro** vueltas en vez de dos, porque `for` parte también por el espacio de "Hiroshi Nohara".
>
> Y no da error: simplemente hace algo distinto de lo que querías. Si eso fuera un bucle que crea usuarios, crearías cuatro usuarios rotos.
>
> **Si cada elemento es una línea, `while IFS= read -r`.** Siempre.

> [!example] Vocabulario de esta práctica
> - **`while`:** repite mientras el comando de la condición tenga éxito.
> - **`read -r`:** lee una línea en una variable. `-r` respeta las barras invertidas.
> - **`IFS=`:** vacía el separador para no recortar espacios.
> - **Here-string (`<<<`):** pasa el contenido de una variable como entrada.
> - **Lista multilínea:** una variable con varias líneas dentro.

> [!info] 🔗 Dónde lo vas a usar
> Es el corazón de los verificadores de las Fases 5 y 7 de Boochan. `while IFS= read -r LINEA; do ... done <<< "$CRUCES"` recorre la matriz de permisos cruzados, y otro igual recorre `$PROHIBIDOS`. Cuando abras `verificar_fase7.sh` con `less`, esas dos estructuras son la mitad del fichero.

> [!example] Paso 1 — Fabrica una lista multilínea
> ```
> CRUCES="facturacion:comercial:r-x
> facturacion:contabilidad:rwx
> comercial:logistica:r-x
> becarios:rrhh:r-x"
>
> echo "$CRUCES"
> echo "$CRUCES" | wc -l
> ```
>
> Cuatro líneas dentro de una sola variable. Fíjate en que el salto de línea va **dentro de las comillas**.

> [!example] Paso 2 — Comprueba que `for` no sirve aquí
> ```
> for c in $CRUCES; do echo "[$c]"; done
> ```
>
> Aquí funciona por casualidad, porque no hay espacios. Métele uno:
>
> ```
> CRUCES_CON_ESPACIOS="facturacion:comercial:solo lectura
> becarios:rrhh:solo lectura"
>
> for c in $CRUCES_CON_ESPACIOS; do echo "[$c]"; done
> ```
>
> **Cuatro vueltas en vez de dos.** Ahí tienes el problema.

> [!example] Paso 3 — Ahora con `while read`
> ```
> while IFS= read -r LINEA; do
>     echo "[$LINEA]"
> done <<< "$CRUCES_CON_ESPACIOS"
> ```
>
> Dos vueltas, dos líneas completas. Cada renglón entero, con sus espacios.

> [!example] Paso 4 — Comprueba para qué está cada pieza
> ```
> CON_ESPACIOS="   linea con espacios delante y detras   "
>
> while read -r L; do echo "[$L]"; done <<< "$CON_ESPACIOS"
> while IFS= read -r L; do echo "[$L]"; done <<< "$CON_ESPACIOS"
> ```
>
> Sin `IFS=`, los espacios del principio y del final **desaparecen**. Con `IFS=`, se respetan.
>
> Y la `-r`:
>
> ```
> CON_BARRA='ruta\nfalsa'
> while IFS= read L; do echo "[$L]"; done <<< "$CON_BARRA"
> while IFS= read -r L; do echo "[$L]"; done <<< "$CON_BARRA"
> ```
>
> Sin `-r`, la barra se interpreta y se pierde información. **Por eso se escribe siempre `IFS= read -r`, las tres piezas juntas.** No es superstición.

> [!example] Paso 5 — Parte cada línea en sus campos
> ```
> while IFS= read -r LINEA; do
>     [ -z "$LINEA" ] && continue
>     CARPETA=$(echo "$LINEA" | cut -d: -f1)
>     GRUPO=$(echo "$LINEA"   | cut -d: -f2)
>     PERM=$(echo "$LINEA"    | cut -d: -f3)
>     echo "En '$CARPETA', el grupo '$GRUPO' tendra '$PERM'"
> done <<< "$CRUCES"
> ```
>
> `cut` del `EJ-03-03-01`, ahora dentro del bucle. Y el `[ -z "$LINEA" ] && continue` salta las líneas vacías: sin él, una línea en blanco al final te genera una vuelta fantasma.
>
> **Este bloque es, casi carácter por carácter, el bloque B del `verificar_fase7.sh` de Boochan.**

> [!example] Paso 6 — La otra forma de partir: `IFS=':' read`
> ```
> while IFS=':' read -r CARPETA GRUPO PERM; do
>     [ -z "$CARPETA" ] && continue
>     echo "carpeta=$CARPETA  grupo=$GRUPO  perm=$PERM"
> done <<< "$CRUCES"
> ```
>
> Aquí `IFS=':'` en vez de vacío: `read` **parte la línea por los dos puntos** y reparte los trozos en tres variables de golpe. Sin `cut`, sin sustituciones.
>
> Es más elegante y hace tres procesos menos. Y es exactamente lo que hace la **Fase 5 de Boochan**:
>
> ```
> IFS=':' read -r LOGIN UID_N GID_N GRUPO NOMBRE APELLIDO <<< "$u"
> ```
>
> Seis variables de una línea. Ya la puedes leer entera.

> [!example] Paso 7 — Aplícalo de verdad
> ```
> cd ~
> nano aplicar-matriz.sh
> ```
>
> ```

## 🚩 Errores y verificación

> [!warning] Errores típicos (evítalos)
> | Error | Qué pasa | Cómo evitarlo |
> | :--- | :--- | :--- |
> | `for` sobre líneas con espacios | Cada palabra es una vuelta | `while IFS= read -r`. |
> | Olvidar `IFS=` | Se recortan los espacios del principio y del final | Escríbelo siempre: `IFS= read -r`. |
> | Olvidar `-r` | Las barras invertidas se interpretan y se pierden datos | `read -r`, siempre. |
> | No saltar las líneas vacías | Una vuelta fantasma con datos vacíos | `[ -z "$LINEA" ] && continue`. |

> [!success] ✅ Verificación: ¿está bien hecho?
> - Has visto a `for` partir mal una línea con espacios.
> - `while IFS= read -r` recorre línea a línea correctamente.
> - Has comprobado qué pasa sin `IFS=` y sin `-r`.
> - Tu script aplica la matriz completa desde una lista multilínea.
