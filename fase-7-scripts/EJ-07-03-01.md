## EJ-07-03-01 — Marko decide con `if` y códigos de salida

> [!abstract] Ficha de la práctica
> ### 📌 `B0.S.7.3.1` — Marko decide con `if` y códigos de salida
> - **Fase 7** (Leer y escribir un script de bash) · **Nivel 3** (Medio)
> - **🎬 Playlist:** `B0_Curso_Shell`
> - **📹 Nombre del vídeo:** `B0.S.7.3.1 · Marko decide con if y codigos de salida`

> [!info] Situación
> El script de Marko crea las carpetas sin mirar nada. Si el grupo no existe, `chown` falla, el script sigue tan tranquilo y al final dice que todo ha ido bien. Lucía: *"Un script que siempre dice que todo está bien no sirve para nada. Que compruebe."*

- **🎯 Objetivo real:** hacer que el script **decida**: compruebe una condición y actúe según el resultado.
- **🧩 Problema que resuelve:** hasta ahora tus scripts ejecutan a ciegas. Un verificador **tiene que comprobar y opinar**: `[OK]` o `[FALLO]`. Sin `if`, eso es imposible.

> [!info] Antes de empezar: bash decide con códigos de salida
> Esto es lo que hay que entender antes que la sintaxis: **`if` no evalúa una expresión, ejecuta un comando y mira su código de salida.**
>
> Ya conoces `$?` del `EJ-03-01-02`: `0` = fue bien, distinto de `0` = falló.
>
> ```
> if grep -q "root" /etc/passwd; then
>     echo "está"
> else
>     echo "no está"
> fi
> ```
>
> Ahí no hay ninguna comparación: **se ejecuta `grep -q` y se mira si devolvió 0**.
>
> Y `[ ... ]` es un **comando** como cualquier otro *(literalmente existe `/usr/bin/[`)* que devuelve 0 o 1 según lo que le preguntes. Por eso necesita espacios: son sus argumentos.
>
> Las comprobaciones que se usan de verdad:
>
> | Prueba | Cierta cuando |
> | :--- | :--- |
> | `[ -z "$VAR" ]` | la variable está **vacía** |
> | `[ -n "$VAR" ]` | la variable **tiene algo** |
> | `[ "$A" = "$B" ]` | dos textos son iguales |
> | `[ "$A" != "$B" ]` | son distintos |
> | `[ "$N" -eq 0 ]` | números iguales (`-ne`, `-gt`, `-lt`, `-ge`, `-le`) |
> | `[ -f /ruta ]` | existe y es un **fichero** |
> | `[ -d /ruta ]` | existe y es un **directorio** |
> | `[ -e /ruta ]` | existe, sea lo que sea |
> | `! condición` | niega |
>
> Y la forma corta, que verás por todas partes:
>
> ```
> comando && echo "fue bien"        # ejecuta lo de la derecha SOLO si fue bien
> comando || echo "falló"           # ejecuta lo de la derecha SOLO si falló
> [ "$FALLOS" -eq 0 ] && exit 0 || exit 1
> ```
>
> Esa última línea es literalmente la última del `verificar_fase7.sh` de Boochan.

> [!tip] Idea clave
> `if` es **el control de calidad al final de la cinta**. La pieza pasa, se mide, y según la medida va a la caja de buenas o a la de rechazos. Sin control, la cinta escupe piezas y nadie sabe si valen — que es justo lo que hacía el script de Marko.

> [!warning] El error nº1: escribir `[ ... ]` sin espacios
> ```
> if [ "$PERM"="2770" ]; then
> ```
>
> **Esto siempre es cierto.** Sin espacios alrededor del `=`, bash no ve una comparación: ve **una sola cadena de texto** no vacía, y una cadena no vacía es "verdadero".
>
> Resultado: tu `if` entra siempre, tu verificador siempre dice `[OK]`, y no comprueba nada.
>
> **Y no da ningún error.** Es el fallo más traicionero de bash entero.
>
> ```
> if [ "$PERM" = "2770" ]; then     # correcto: espacios a los dos lados
> ```
>
> Regla: dentro de `[ ]`, **todo lleva espacios**. Los corchetes también.

> [!example] Vocabulario de esta práctica
> - **Código de salida:** el número que devuelve un comando: `0` bien, otro mal.
> - **`[ ... ]`:** un comando que evalúa una condición. Necesita espacios.
> - **`-z` / `-n`:** variable vacía / no vacía.
> - **`-eq -ne -gt -lt`:** comparaciones **numéricas**.
> - **`&&` / `||`:** "y si fue bien" / "o si falló".

> [!info] 🔗 Dónde lo vas a usar
> Es el esqueleto de los siete verificadores de Boochan. `if [ "$EUID" -ne 0 ]; then echo "ERROR: ejecutalo con sudo"; exit 1; fi` al principio. `if [ -z "$FALTAN" ]; then ok ...; else fallo ...; fi`. `if [ "$PERM_BEC" = "2750" ]`. Y el cierre: `[ "$FALLOS" -eq 0 ] && exit 0 || exit 1`.

> [!example] Paso 1 — Comprueba que `if` mira el código de salida
> ```
> grep -q "root" /etc/passwd ; echo $?
> grep -q "noexiste" /etc/passwd ; echo $?
>
> if grep -q "root" /etc/passwd; then echo "SI está"; else echo "NO está"; fi
> if grep -q "noexiste" /etc/passwd; then echo "SI está"; else echo "NO está"; fi
> ```
>
> **No hay ninguna comparación en esos `if`.** Solo se ejecuta el comando y se mira si devolvió 0.

> [!example] Paso 2 — Comprueba que `[ ]` es un comando
> ```
> [ "hola" = "hola" ] ; echo $?
> [ "hola" = "adios" ] ; echo $?
> type [
> ```
>
> Devuelve 0 o 1, como cualquier comando. Y `type` te confirma que es una orden de verdad.
>
> Por eso hacen falta los espacios: son **argumentos**.

> [!example] Paso 3 — Reproduce el error nº1
> ```
> PERM="2750"
>
> if [ "$PERM"="2770" ]; then echo "entra"; else echo "no entra"; fi
> if [ "$PERM" = "2770" ]; then echo "entra"; else echo "no entra"; fi
> ```
>
> El primero dice `entra` **y `$PERM` vale 2750**. El segundo, correcto.
>
> Un espacio. Y ningún error. Dilo en voz alta en el vídeo: es el fallo que hace que un verificador mienta.

> [!example] Paso 4 — Prueba las comprobaciones que vas a usar
> ```
> VACIA=""
> LLENA="algo"
>
> [ -z "$VACIA" ] && echo "VACIA está vacía"
> [ -n "$LLENA" ] && echo "LLENA tiene algo"
> [ -d /etc ] && echo "/etc es un directorio"
> [ -f /etc/passwd ] && echo "/etc/passwd es un fichero"
> [ -f /etc ] || echo "/etc NO es un fichero"
> [ 5 -gt 3 ] && echo "5 es mayor que 3"
> ```
>
> Y la negación:
>
> ```
> if ! command -v setfacl >/dev/null 2>&1; then
>     echo "FALTA el paquete acl"
> else
>     echo "acl instalado"
> fi
> ```
>
> **Ese `if !` con `command -v` es literal del `verificar_fase7.sh`.** Ya lo puedes leer entero.

> [!example] Paso 5 — Escribe un verificador de verdad
> ```
> cd ~
> nano verificar-mis-deptos.sh
> ```
>
> ```
> #!/bin/bash
> # verificar-mis-deptos.sh - comprueba la estructura de departamentos
> # Marko - Boochan Networks S.L.
>
> BASE="/srv/lab/departamentos"
> DEPARTAMENTOS="facturacion contabilidad comercial logistica rrhh becarios"
>
> if [ "$EUID" -ne 0 ]; then
>     echo "ERROR: ejecutalo con sudo   ->   sudo ./verificar-mis-deptos.sh"
>     exit 1
> fi
>
> echo "=== Verificacion de $BASE ==="
>
> if [ ! -d "$BASE" ]; then
>     echo "[FALLO] No existe $BASE"
>     exit 1
> fi
>
> for d in $DEPARTAMENTOS; do
>     RUTA="$BASE/$d"
>
>     if [ ! -d "$RUTA" ]; then
>         echo "[FALLO] $d: no existe la carpeta"
>         continue
>     fi
>
>     GRUPO=$(stat -c %G "$RUTA" 2>/dev/null)
>     PERM=$(stat -c %a "$RUTA" 2>/dev/null)
>
>     if [ "$GRUPO" != "$d" ]; then
>         echo "[FALLO] $d: el grupo es '$GRUPO' y deberia ser '$d'"
>     elif [ "$PERM" != "2770" ]; then
>         echo "[FALLO] $d: permisos $PERM, deberian ser 2770"
>     else
>         echo "[OK]    $d: grupo y permisos correctos"
>     fi
> done
> ```
>
> ```
> chmod +x verificar-mis-deptos.sh
> ./verificar-mis-deptos.sh
> sudo ./verificar-mis-deptos.sh
> ```
>
> El primero te para en seco: es la comprobación de `$EUID`. El segundo funciona.
>
> Fíjate en `continue`: **salta a la siguiente vuelta del bucle**. Si la carpeta no existe, no tiene sentido mirarle los permisos.

> [!example] Paso 7 — Devuelve un código de salida honesto
> Primero, **declara el contador arriba del todo**, justo debajo del `#!/bin/bash`:
>
> ```
> FALLOS=0
> ```
>
> Y ahora, al final del script:
>
> ```
> echo ""
> if [ "$FALLOS" -eq 0 ]; then
>     echo "VEREDICTO: TODO CORRECTO"
>     exit 0
> else
>     echo "VEREDICTO: $FALLOS FALLO(S)"
>     exit 1
> fi
> ```
>
> **Ojo a lo que hace ahora mismo:** el contador está a `0` y **nadie lo incrementa todavía**, así que el veredicto va a decir siempre *"TODO CORRECTO"*, aunque algo falle. **Eso es un verificador que miente**, y es exactamente el fallo que vas a arreglar en el [EJ-07-04-02](EJ-07-04-02.md).

> > Verás `integer expression expected` y un veredicto imposible. No es que hayas hecho nada mal: **es lo que pasa cuando `[ ]` compara una variable que no existe**. Declárala y desaparece.

## 🚩 Errores y verificación

> [!warning] Errores típicos (evítalos)
> | Error | Qué pasa | Cómo evitarlo |
> | :--- | :--- | :--- |
> | `[ "$A"="$B" ]` sin espacios | **Siempre cierto**, sin dar error. Tu verificador miente | Espacios a los dos lados del `=`. |
> | Comparar números con `=` | Compara textos: `"07"` y `"7"` no son iguales | `-eq`, `-ne`, `-gt`, `-lt` para números. |
> | No entrecomillar en `[ ]` | Si la variable está vacía, error de sintaxis raro | `[ "$VAR" = ... ]`. |
> | Olvidar `fi` | La shell se queda esperando | Todo `if` se cierra con `fi`. |
