## EJ-07-04-02 — Marko escribe funciones y cuenta los fallos

> [!abstract] Ficha de la práctica
> ### 📌 `B0.S.7.4.2` — Marko escribe funciones y cuenta los fallos
> - **Fase 7** (Leer y escribir un script de bash) · **Nivel 4** (Avanzado)
> - **🎬 Playlist:** `B0_Curso_Shell`
> - **📹 Nombre del vídeo:** `B0.S.7.4.2 · Marko escribe funciones y cuenta los fallos`

> [!info] Situación
> El verificador de Marko tiene veinte comprobaciones y en cada una repite las mismas tres líneas: pintar el mensaje, escribirlo en el informe y sumar uno al contador. Sesenta líneas casi iguales. Y al final el script no sabe decir cuántos fallos hubo.

- **🎯 Objetivo real:** agrupar código repetido en funciones y llevar un recuento que decida el veredicto final.
- **🧩 Problema que resuelve:** sin funciones, cambiar el formato del informe significa tocar veinte sitios. Y sin contador, un verificador no puede decir si el resultado es apto.

> [!info] Antes de empezar: funciones, parámetros y contadores
> Una **función** es un bloque de código con nombre:
>
> ```
> ok() {
>     echo "[OK]    $1"
>     echo "[OK]    $1" >> "$INFORME"
> }
>
> ok "Los 6 grupos son visibles"
> ```
>
> - `$1` es el **primer argumento** que le pasas. `$2` el segundo, y así.
> - Se define **antes** de usarla: bash lee el fichero de arriba abajo.
> - Se llama por su nombre, sin paréntesis.
>
> Y el **contador**, con la aritmética del `EJ-07-02-01`:
>
> ```
> FALLOS=0
>
> fallo() {
>     echo "[FALLO] $1"
>     FALLOS=$((FALLOS+1))
> }
> ```
>
> `$(( ))` hace aritmética. Y aquí sí, `FALLOS=$((FALLOS+1))` **sin espacios** alrededor del `=`, como toda asignación.
>
> El esqueleto completo de un verificador, que es lo que estás construyendo:
>
> ```
> INFORME="verificacion.txt"
> FALLOS=0
> AVISOS=0
>
> ok()    { echo "[OK]    $1"; echo "[OK]    $1" >> "$INFORME"; }
> fallo() { echo "[FALLO] $1"; echo "[FALLO] $1" >> "$INFORME"; FALLOS=$((FALLOS+1)); }
> aviso() { echo "[AVISO] $1"; echo "[AVISO] $1" >> "$INFORME"; AVISOS=$((AVISOS+1)); }
> info()  { echo "        $1"; echo "        $1" >> "$INFORME"; }
>
> # ... comprobaciones ...
>
> [ "$FALLOS" -eq 0 ] && exit 0 || exit 1
> ```
>
> **Esas cuatro funciones son, literalmente, las de los siete verificadores de Boochan.**

> [!tip] Idea clave
> Una función es **un sello de goma**. En vez de escribir a mano "RECIBIDO" y la fecha en doscientos documentos, tallas el sello una vez. Y si mañana hay que cambiar el texto, cambias el sello, no los doscientos documentos.

> [!warning] El error nº1: definir la función después de llamarla
> ```
> ok "todo bien"
>
> ok() { echo "[OK] $1"; }
> ```
>
> ```
> ok: orden no encontrada
> ```
>
> Bash lee el fichero **de arriba abajo**. Cuando llega a la llamada, la función todavía no existe.
>
> **Las funciones van arriba**, justo después de las variables. Mira cualquier verificador de Boochan: variables, funciones, comprobación de root, y a partir de ahí el trabajo.
>
> El segundo error de esta familia: usar `$1` **fuera** de la función. Dentro de una función, `$1` es su argumento; fuera, es el argumento del script entero. No son lo mismo.

> [!example] Vocabulario de esta práctica
> - **Función:** bloque de código con nombre, reutilizable.
> - **`$1`, `$2`:** los argumentos que recibe la función.
> - **`$(( ))`:** aritmética. `FALLOS=$((FALLOS+1))`.
> - **Contador:** variable que acumula un recuento.
> - **Veredicto:** la conclusión del script, que se refleja en su `exit`.

> [!info] 🔗 Dónde lo vas a usar
> Los siete verificadores de Boochan tienen **exactamente estas cuatro funciones**, definidas igual, con los mismos nombres y los mismos colores ANSI. Y todos acaban con el veredicto y `[ "$FALLOS" -eq 0 ] && exit 0 || exit 1`. Al acabar este ejercicio podrás leer un `verificar_faseN.sh` de principio a fin.

> #!/bin/bash
> probar "primera llamada"

> probar() { echo "[OK] $1"; }

> ```

> chmod +x orden.sh

> ```

> [!example] Paso 3 — Contadores y aritmética
> ```
> FALLOS=0
> echo "$FALLOS"
> FALLOS=$((FALLOS+1))
> FALLOS=$((FALLOS+1))
> echo "$FALLOS"
>
> echo $((3 * 7))
> echo $((10 / 3))
> ```
>
> `$(( ))` hace aritmética entera. La división trunca: `10/3` da `3`. Para un contador de fallos sobra.

> [!example] Paso 4 — Monta el esqueleto de verificador
> ```
> cd ~
> nano verificar-v2.sh
> ```
>
> ```
> #!/bin/bash
> # verificar-v2.sh - verificador de la estructura de departamentos
> # Marko - Boochan Networks S.L.
> #
> # USO:  chmod +x verificar-v2.sh
> #       sudo ./verificar-v2.sh
> #
> # El informe se guarda en verificacion.txt, en la carpeta actual.
>
> INFORME="verificacion.txt"
> BASE="/srv/lab/departamentos"
> DEPARTAMENTOS="facturacion contabilidad comercial logistica rrhh becarios"
> FALLOS=0
> AVISOS=0
>
> V='\033[0;32m'; R='\033[0;31m'; A='\033[0;33m'; N='\033[0m'
>
> ok()    { echo -e "${V}[OK]   ${N} $1"; echo "[OK]    $1" >> "$INFORME"; }
> fallo() { echo -e "${R}[FALLO]${N} $1"; echo "[FALLO] $1" >> "$INFORME"; FALLOS=$((FALLOS+1)); }
> aviso() { echo -e "${A}[AVISO]${N} $1"; echo "[AVISO] $1" >> "$INFORME"; AVISOS=$((AVISOS+1)); }
> info()  { echo "        $1"; echo "        $1" >> "$INFORME"; }
>
> if [ "$EUID" -ne 0 ]; then
>     echo "ERROR: ejecutalo con sudo   ->   sudo ./verificar-v2.sh"
>     exit 1
> fi
>
> {
>   echo "============================================================"
>   echo " VERIFICACION DE LA ESTRUCTURA DE DEPARTAMENTOS"
>   echo " Fecha:    $(date '+%Y-%m-%d %H:%M:%S')"
>   echo " Servidor: $(hostname)"
>   echo "============================================================"
> } > "$INFORME"
> cat "$INFORME"
> ```
>
> Esas variables `V`, `R`, `A`, `N` son **códigos de color ANSI**: `\033[0;32m` pone el texto en verde y `\033[0m` lo devuelve a normal. El `-e` de `echo` es lo que hace que se interpreten.
>
> No hace falta memorizarlos. Sí saber **qué son** cuando los veas en Boochan, para no pensar que es basura.

> [!example] Paso 5 — Añade las comprobaciones
> Sigue en el mismo fichero:
>
> ```
> echo "" | tee -a "$INFORME"
> echo "--- A. Los grupos ---" | tee -a "$INFORME"
>
> FALTAN=""
> for d in $DEPARTAMENTOS; do
>     getent group "$d" >/dev/null 2>&1 || FALTAN="$FALTAN $d"
> done
>
> if [ -z "$FALTAN" ]; then
>     ok "A1. Los 6 grupos de departamento son visibles"
> else
>     fallo "A1. No se ven estos grupos:$FALTAN"
>     info "     Sin los grupos, los permisos apuntarian a la nada."
> fi
>
> echo "" | tee -a "$INFORME"
> echo "--- B. Las carpetas ---" | tee -a "$INFORME"
>
> N=0
> for d in $DEPARTAMENTOS; do
>     N=$((N+1))
>     RUTA="$BASE/$d"
>
>     if [ ! -d "$RUTA" ]; then
>         fallo "B$N. $d: no existe la carpeta"
>         continue
>     fi
>
>     GRUPO=$(stat -c %G "$RUTA" 2>/dev/null)
>     GRUPO="${GRUPO##*\\}"
>     PERM=$(stat -c %a "$RUTA" 2>/dev/null)
>
>     if [ "$GRUPO" != "$d" ]; then
>         fallo "B$N. $d: el grupo es '$GRUPO', deberia ser '$d'"
>         info "     Arreglo: sudo chown root:$d $RUTA"
>     elif [ "${PERM:-0}" != "2770" ]; then
>         fallo "B$N. $d: permisos $PERM, deberian ser 2770"
>         info "     Arreglo: sudo chmod 2770 $RUTA"
>     else
>         ok "B$N. $d: grupo y permisos correctos"
>     fi
> done
> ```
>
> Fíjate en cuánto has reutilizado: `for`, `if`, `stat`, `${GRUPO##*\\}`, `${PERM:-0}`, `continue`. **Todo el curso está en estas veinte líneas.**

> [!example] Paso 6 — Añade el veredicto
> ```
> echo "" | tee -a "$INFORME"
> echo "============================================================" | tee -a "$INFORME"
> if [ "$FALLOS" -eq 0 ] && [ "$AVISOS" -eq 0 ]; then
>     echo " VEREDICTO: ESTRUCTURA CORRECTA" | tee -a "$INFORME"
> elif [ "$FALLOS" -eq 0 ]; then
>     echo " VEREDICTO: CORRECTA CON $AVISOS AVISO(S)" | tee -a "$INFORME"
> else
>     echo " VEREDICTO: $FALLOS FALLO(S)" | tee -a "$INFORME"
> fi
> echo "============================================================" | tee -a "$INFORME"
>
> if [ -n "$SUDO_USER" ]; then
>     chown "$SUDO_USER":"$SUDO_USER" "$INFORME" 2>/dev/null
> fi
>
> echo ""
> echo "Informe guardado en: $(pwd)/$INFORME"
>
> [ "$FALLOS" -eq 0 ] && exit 0 || exit 1
> ```
>
> Ese `chown "$SUDO_USER"` del final está en todos los verificadores de Boochan y tiene su razón: el script corre como root, así que el informe **nace siendo de root** y el alumno no puede subirlo a su repositorio. `$SUDO_USER` guarda quién lanzó el `sudo`.
>
> **Un detalle de cortesía que solo se le ocurre a quien ha usado la herramienta.**

## 🚩 Errores y verificación

> [!warning] Errores típicos (evítalos)
> | Error | Qué pasa | Cómo evitarlo |
> | :--- | :--- | :--- |
> | Definir la función después de llamarla | `orden no encontrada` | Las funciones, arriba del todo. |
> | Espacios en `FALLOS = $((...))` | `FALLOS: orden no encontrada` | Asignación pegada, como toda variable. |
> | Olvidar el `exit` final | El script devuelve el código del último comando, que no significa nada | `[ "$FALLOS" -eq 0 ] && exit 0 || exit 1`. |
> | Dejar el informe siendo de root | El alumno no puede subirlo a su repositorio | `chown "$SUDO_USER"` al final. |

> [!success] ✅ Verificación: ¿está bien hecho?
> - Tu script usa las cuatro funciones y no repite código.
> - El contador refleja el número real de fallos.
> - El código de salida es `0` cuando todo va bien y `1` cuando no.
> - El informe queda en un fichero y pertenece a tu usuario, no a root.
